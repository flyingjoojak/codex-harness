# web-ui

이 화면은 담당자가 결과를 보고 결정하는 업무 도구다. 장식이 아니라 바로 읽히고 쓰기 좋은 완성도로 승부한다.
화면도 결과물의 일부다. 첫 완주는 기능 위주로 하고, 품질 올리기 구간에서 사용성과 완성도를 끌어올린다. 동결 뒤에는 손대지 않는다.

## 먼저
- 과제에 이미 프레임워크, 템플릿, CSS 가 있으면 그 스타일을 따른다. 새 UI 라이브러리를 들이지 않는다.
- CDN 에 의존하지 않는다(인터넷 여부 미확인). 순수 HTML/CSS 또는 이미 설치된 것만.

## 피할 것 (AI 티)
- 보라, 파랑 그라디언트 배경, 유리 효과, 네온 그림자
- 이모지 아이콘, "AI-powered", "Welcome to ..." 같은 가운데 정렬 히어로 문구
- 의미 없는 통계 카드 4개, 모든 요소에 같은 둥근 모서리와 그림자
- 동작하지 않는 버튼, 가짜 데이터, lorem ipsum, 요구사항에 없는 메뉴와 탭
- 과한 애니메이션

## 할 것
- 첫 화면에 핵심 결과(숫자, 표, 판정)를 바로 보여준다. 설명 문단은 한두 줄.
- 표: 글자는 왼쪽, 숫자는 오른쪽 정렬, 단위와 기준값 표시. 정렬 기준을 정하고 동률 규칙을 지킨다.
- 색은 의미에만 쓴다(위반, 경고, 정상). 색만으로 구분하지 않고 글자도 함께 쓴다.
- 색은 CSS 변수 3~4개(배경, 글자, 강조, 경고). 글꼴은 시스템 글꼴. 여백은 일정한 간격 단위 하나로.
- 빈 결과, 오류, 처리 중 상태 문구를 만든다. 오류 문구는 "무엇을 하면 되는지" 한 줄.
- 문구는 담당자가 쓰는 업무 용어로. 한국어.
- 버튼과 입력에는 label 을 붙이고 키보드로도 쓸 수 있게.

## 확인
- 서버는 `0.0.0.0` 으로 띄우고 내장 브라우저로 본다.
- 담당자 시나리오 하나(입력 > 결과 확인 > 결정)를 처음부터 끝까지 직접 따라가 본다.
- 브라우저 콘솔 오류 0. 좁은 화면에서 가로 스크롤이 생기지 않는지.
- 화면의 숫자가 테스트나 계산 코드 결과와 같은지 하나 이상 대조한다.
