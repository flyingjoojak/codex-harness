# llm-feature

원칙: 판정과 계산은 규칙(코드)이 하고, LLM 은 말로 풀어야 하는 부분만 맡는다. LLM 출력은 입력 데이터로 검증하기 전까지 믿지 않는다.

## 1. 연결 확인 (값은 출력하지 않는다)
- 과제 README 에서 엔드포인트, 모델 이름, 키 변수 이름을 찾는다. 모델 이름은 추측하지 않는다.
- `python3 -c "import os; print({k: bool(os.getenv(k)) for k in ['OPENAI_API_KEY','OPENAI_BASE_URL']})"` 로 있는지만 본다.
- `python3 -c "import openai"` 가 실패하면 `requests` 로 OpenAI 호환 `/chat/completions` 를 직접 부른다.
- 한 번 호출해 응답 형식을 확인하고, 그 응답을 `fixtures/` 에 저장한다(테스트용).
- 키는 환경변수로만 읽는다. 코드, 로그, 커밋, README 에 값을 쓰지 않는다.

## 2. 구조
```
입력 > 규칙 필터/판정(코드) > LLM(문구, 분류 보조) > 출력 검증 > 결과
                                   실패 시 > 규칙 기반 대체 문구
```
- LLM 호출은 함수 하나(`call_llm`)에 모은다. 타임아웃(예: 30초), 재시도 1회, 실패 시 예외 대신 대체 경로.
- 결정성: temperature 0, 같은 입력은 파일 캐시로 재사용(결과 재현, 속도).
- 품질에 필요하면 충분히 부른다. 다만 묶어서 부를 수 있으면 묶어 속도를 확보하고, 실패나 지연 때 전체가 멈추지 않게 한다.

## 3. 출력 검증 (가드레일)
- 형식: JSON 으로 받고 필수 키, 타입, 허용 값 목록을 코드로 검사한다. 실패하면 대체 경로.
- 근거: LLM 이 말한 사실(이름, 숫자, 상품, 조건)이 입력 데이터에 실제로 있는지 대조한다. 없으면 버린다.
- 금지 표현이 있으면: 공백, 특수문자를 지우고 소문자로 맞춘 뒤 포함 여부를 검사한다(띄어쓰기 우회 대비).
- 숫자는 LLM 에게 계산시키지 않는다. 코드가 계산한 값을 넣어 주고 문장만 만들게 한다.

## 4. 테스트
- 테스트에서는 네트워크를 부르지 않는다. `call_llm` 을 가짜 함수나 저장한 fixture 로 바꾼다.
- 꼭 둘 것: 정상 응답 / 형식이 깨진 응답 / 데이터에 없는 사실을 말한 응답 / 금지 표현 / 타임아웃. 각각 대체 경로나 차단이 동작하는지.

## 5. 보고에 넣을 숫자
- 전체 N 건 중 LLM 사용 X, 대체 경로 Y, 가드레일 차단 Z(사유별).
- 프롬프트는 파일(`prompts/`)로 두고 바꿀 때마다 커밋한다. 서술형에서 "왜 이 프롬프트인가"를 답할 근거가 된다.
