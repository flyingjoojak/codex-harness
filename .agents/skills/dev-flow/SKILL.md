# dev-flow

시간 제한 과제용. 사람의 승인은 계약 끝에서 한 번 받고, 이후는 단계마다 세 줄 보고하며 진행한다.

## 1. 읽기 (코드 금지)
- 과제 README, 파일 목록, 데이터 형식, 제출 형식을 읽는다. 데이터는 `python3 ~/codex-harness/tools/peek.py <파일>` 로 구조만 본다.
- 출력: "무엇을 만드는지" 한 문장.

## 2. 계약
1. `TASK.md` 의 한 문장, 사실, 가정, 열린 질문, 안 할 일, 완료 조건을 채운다.
   - 사실은 과제에 글자로 쓰인 것만. 출처를 붙인다.
   - 가정에는 "틀리면 무엇이 깨지나"를 같이 쓴다.
   - 완료 조건마다 테스트 이름(`test_...`)을 붙인다. 테스트 이름이 없으면 완료 조건이 아니다.
2. 담당자(사람이든 AI 든)가 있으면 `~/codex-harness/docs/담당자_인터뷰.md` 순서로 질문 목록을 만들어 사람에게 넘긴다. 답을 `TASK.md` 에 반영한다.
3. 합의문(문제 / 성공 기준 / 만들 것 / 안 만들 것 / 제약)을 `DECISIONS.md` 맨 위에 적는다.
4. 요약을 보여주고 "진행할까요?"에서 멈춘다.

## 3. 첫 완주 (전체 시간의 35% 안에)
- 규칙을 다 채우지 않은 상태로 입력 > 처리 > 제출 파일까지 한 번 돈다. 형식 확인까지.
- 커밋하고 "제출 가능 상태"라고 알린다. 걸린 시간을 잰다.

## 4. 규칙 채우기
- 완료 조건 하나씩: 테스트 작성 > 실패 확인 > 최소 구현 > 통과 > 출력 직접 확인 > 커밋.
- 테스트는 pytest(`python3 -m pytest -q`). 시험 환경에 설치돼 있다.
- 그 다음 엣지 케이스: 결측, 빈 입력, 경계값, 중복, 순서, 형식 오류.
- 막히면 `$systematic-debugging`. 15분 넘게 막히면 그 기능을 `안 할 일` 로 옮기고 기록한다.

## 5. 동결 (마지막 20%)
- 기능 추가 금지. `$review-checklist` > `$verify` > README 와 문서 정리.
- 마지막으로 `DECISIONS.md` 맨 아래 '서술형 카드'를 15줄 이내로 쓴다(사람이 서술형 직전에 외울 요약). 각 줄에 근거 파일:줄 또는 커밋을 붙이고, 근거 없는 내용은 쓰지 않는다. 항목: 한 문장 요약, 사용자와 돕는 결정, 핵심 결정 3개(이유, 버린 대안), 지킨 조건과 조정한 것, 가정 2개, 검증 숫자, 가장 약한 입력, Codex 를 믿지 않은 순간, 안 한 것, 시간이 두 배라면.
