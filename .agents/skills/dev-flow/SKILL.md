# dev-flow

시간 제한이 있는 과제용이다. 사용자 승인은 STEP 1 끝에서 한 번만 받고, 이후는 단계마다 짧게 보고하며 진행한다.

## STEP 1 - 계약 (최대 15분)
1. 과제 설명, 주어진 파일, 데이터를 모두 훑는다. 큰 파일은 앞부분과 구조만.
2. `TASK.md` 를 채운다.
   - 목적: 이 과제가 해결하는 문제 한 줄
   - 입력 / 출력: 형식까지 정확히
   - 인수 기준: 측정 가능한 문장으로(예: "샘플 입력 3개에 대해 기대 출력과 일치")
   - 엣지 케이스
   - 범위 밖
   - 가정: 과제에 없는데 정해야 하는 것
3. 불명확한 항목은 질문을 한 번에 모아 묻는다. 답이 없으면 가정으로 적고 진행한다.
4. 출력: `TASK.md` 요약 + "진행할까요?" 한 줄. 여기서 멈춘다.

## STEP 2 - 계획
- 가장 작은 동작하는 버전(제출 가능한 최소본)을 먼저 정한다.
- 태스크를 3~7개로 나누고 각각 완료 기준을 한 줄씩. `TASK.md` 아래에 적는다.
- 기술 선택은 이미 설치된 것 우선. 선택 이유를 `DECISIONS.md` 에 한 줄.

## STEP 3 - 테스트 먼저
- 인수 기준을 테스트로 옮긴다(Python 이면 pytest, 아니면 그 언어 기본 도구).
- 실행해서 실패를 확인하고 결과를 보고한다.

## STEP 4 - 구현
- 태스크 하나씩: 최소 코드로 통과 > 정리 > `git commit`.
- 실패하면 `$systematic-debugging`.
- 최소본이 통과하면 바로 커밋하고 "제출 가능 상태"라고 알린다. 개선은 그 다음.

## STEP 5 - 검증
- `$review-checklist` 로 자체 리뷰 > `$verify` 로 최종 확인.

## 단계 보고 형식
```
[STEP N 완료] 한 일 / 확인(명령과 결과) / 다음
```
