# review-checklist

대상: 사용자가 지정한 파일, 없으면 `git diff` 와 최근 커밋의 변경분.

각 관점을 차례로 보고, 해당 없으면 "해당 없음"으로 적는다. 발견은 반드시 파일:줄과 근거를 붙인다. 근거 없는 지적은 올리지 않는다.

| 관점 | 볼 것 |
|---|---|
| 정확성 | 인수 기준(`TASK.md`)을 전부 만족하는가, 경계값, off-by-one, 빈 입력, 형식 |
| 무음 실패 | 빈 except, 실패를 무시하는 기본값, 로그 없는 예외 |
| 보안 | 비밀값 하드코딩, 경로 조작, 쿼리 문자열 조립, 검증 안 한 외부 입력 |
| 성능 | 루프 안 반복 I/O, 불필요한 전체 재계산, 데이터 크기에 비해 과한 복잡도 |
| 계약 | 함수/API 입출력 형태, 필드명, 상태코드가 호출하는 쪽과 맞는가 |
| 데이터 | 제외, 변환한 행의 건수와 전후 합계, 빈 값과 0 의 구분, 단위, 반올림, 동률 처리 |
| 단순성 | 요청받지 않은 추상화, 죽은 코드, 중복, 동작하지 않거나 근거 없는 기능 |
| 사용성 | 담당자가 결과를 바로 이해하고 쓸 수 있나. 오류와 빈 결과 안내, 단위, 정렬, 설명 |
| 설명 | 내가 설명하지 못하는 줄이 있나. 있으면 단순하게 바꾸거나 주석 한 줄 |

## 출력
```
CRITICAL / HIGH (지금 고침): ...
MEDIUM (시간이 있으면 고침, 남기면 TASK.md 7번에 이유): ...
LOW (시간 남으면): ...
해당 없음: ...
```
CRITICAL 과 HIGH 는 바로 고치고 테스트를 다시 돌린 결과까지 보고한다.

여유가 있으면 Codex 기본 `/review` 를 한 번 더 돌려 결과를 비교한다.
