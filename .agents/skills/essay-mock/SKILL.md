# essay-mock

전제(추정, 공식 아님): 실제 문항은 LLM 이 제출물을 읽고 만든다. 1회차 문항은 제출물 속 특정 기록(예: AI_COLLABORATION.md 의 Docker 문제)을 그대로 짚었다.
그래서 **제출물에 적은 문장이 곧 문항의 재료**다. 내가 설명하지 못하는 문장은 제출 전에 고치거나 지운다.

## 1. 문항 만들기 (심사자 역할)
아래 역할로 6문항을 `ESSAY_MOCK.md` 에 쓴다. 답은 쓰지 않는다.

> 너는 코딩 시험의 사후 서술형 출제자다. 응시자가 AI 로 만든 제출물을 정말 이해하는지 가려내는 문항을 낸다.
> 읽을 것: 과제 원문(README 또는 과제 파일), 코드, README, AI_COLLABORATION.md, DECISIONS.md, TASK.md, UNDERSTANDING.md, `git log --stat`. 심사 쪽은 AI 대화 기록도 본다고 안내되어 있으니, 내가 요청한 내용 중 방향을 바꾼 요청도 떠올려 반영한다.
> 규칙:
> - 문항마다 제출물의 구체적인 지점 하나를 짚는다(파일, 함수, 기록 문장, 커밋). 일반론 문항은 내지 않는다.
> - 응시자 본인이 쓴 기록과 실제 코드가 어긋나 보이는 곳이 있으면 우선 출제한다.
> - AI 를 쓰지 않고 5분 안에 3~6문장으로 답할 수 있는 크기로 낸다.
> - 문항마다 채점 기준 3개(답에 꼭 있어야 할 사실, 파일 또는 숫자, 한계)를 숨김 절에 따로 적는다.
> 우선 출제 대상(1회차 실제 문항 패턴):
> - 작업 중 바꾼 것: `git log`, DECISIONS.md '방향 전환 기록', 대화에서 구조, 포트, 프레임워크, 저장 방식이 바뀐 지점. "처음엔 X 였는데 Y 로 바꾼 이유와 전환 비용은?"
> - 만든 기능과 못 만든 기능, 못 만든 이유(과제 요구사항과 코드를 대조)
> - 특정 기능 하나가 어떤 과정으로 작동하고 어떤 모듈을 쓰나(가장 많이 고친 파일이나 핵심 기능)
> 나머지 문항은 아래 틀에서 고른다(참가자 공개 기록):
> 1. 핵심 알고리즘, 처리 방식: 단순한 방법 대신 고른 것, 근거(요구사항, 담당자 답), 대안과의 차이, 감수한 한계
> 2. 데이터 흐름: 입력 선택, 검증부터 결과, 화면, 내보내기까지 거치는 모듈. 상태는 어디에 저장되고 누가 소유하나
> 3. 구현하고 검증한 것과 가정으로 둔 것. 평가자는 무엇(테스트, 스크립트, 파일)으로 확인하나
> 4. 요구사항끼리 부딪힌 곳 또는 하지 않기로 한 것과 그 이유(1회차 기록 없음, 추정)
> 5. 데이터 규모나 조건이 크게 바뀌면 결과를 믿기 전에 무엇을 더 검증하나. AI 결과를 무엇으로 판단하나
> 6. AI 협업 기록 속 특정 문제 하나: 어떻게 발견했고, AI 진단 중 무엇을 받아들이거나 고치거나 버렸나. 근거로 본 실행 결과

파일 구조: `## 문항` (6개) 다음에 `## 채점 기준 (답 쓰기 전에 보지 않는다)`.

## 2. 답 쓰기 (사람, AI 없이)
- 문항만 보고 `ESSAY_ANSWER.md` 에 직접 쓴다. 문항당 3분, 사실 > 결정 > 근거(파일, 함수, 숫자) > 한계.
- 막힌 문항은 비워 두고 다음으로 간다(실제 시험도 이전 문항으로 못 돌아간다).

## 3. 채점 (다시 Codex)
문항마다 다음을 표로 낸다: 채점 기준 충족 수(0~3) / **코드와 다른 말**(답 문장, 실제 파일:줄) / 빠진 숫자나 이름 / 고쳐 쓴 4문장 예시.
- "코드와 다른 말"이 가장 중요하다. 하나라도 있으면 그 내용을 서술형 카드에서 고친다.
- 감점 신호(공식 안내 재인용): 교과서 일반론, 없는 파일이나 API 인용, 지어내기. 가점 신호: 제출물과 일치, 버린 대안을 말함.
- 약점, 위험을 묻는 문항은 3단계로 본다(다른 Cofa 대회 후기의 모범 답안 형태): 내 결과물의 구체적 약점 지목 > 왜 위험한가 > 다음에 무엇을 검증하나.
- 막힌 문항은 UNDERSTANDING.md 의 어느 칸이 비어서인지 짚는다.

## 4. 마무리
- 틀린 사실은 서술형 카드(DECISIONS.md 맨 아래)에 바로잡아 적는다.
- 제출물 속 문장 중 설명 못 한 것은 고치거나 지운다(AI_COLLABORATION.md, README 포함).
- `ESSAY_MOCK.md`, `ESSAY_ANSWER.md` 는 제출물에 넣지 않는다(`.git/info/exclude` 에 추가).
