# 바로 쓰는 프롬프트

일을 시킬 때는 네 가지를 넣는다: 목표 / 제약(수정해도 되는 범위) / 완료 기준 / 검증 방법. 끝에 "그다음 멈춰"를 붙이면 다음 단계로 넘어가지 않는다.

## 시작
- AGENTS.md 를 따른다. 적용 중인 지침을 3줄로 요약한 뒤 $dev-flow 1단계부터 시작해. 아직 코드는 쓰지 마.

## 담당자에게 (막혔을 때)
- 과제 맥락을 정확히 이해하고 싶습니다. 현업 관점에서 제가 먼저 확인해야 할 것이 무엇일까요?
- A 조건과 B 조건이 부딪힙니다. 둘 중 어느 쪽을 반드시 지켜야 하나요?
- 시간 안에 전부는 어렵습니다. 결과를 쓰는 분 입장에서 가장 먼저 필요한 것은 무엇인가요?
- 목표가 데이터상 어려우면 꾸미지 말고 두 안을 낸다: A안(지금 충족되는 범위와 한계), B안(목표를 맞추려면 필요한 추가 조건).

## 작게 맡기기
- `test_xxx` 가 통과하게 `src/yyy.py` 만 고쳐. 다른 파일은 건드리지 마. 통과하면 실행 결과를 보여주고 멈춰.
- 이 함수가 하는 일을 코드로 판정하지 말고, 근거 문장 하나씩 표로 보여줘. 커밋은 내가 검토한 뒤에.

## 의심하기
- 이 결론이 틀렸다면 데이터 어디서 드러날지 찾아서 실제로 확인해.
- 합의한 요구사항과 지금 구현을 대조해서, 요구사항에 없는데 들어간 것과 빠진 것을 표로 보여줘.
- 기대값은 코드와 같은 방법으로 계산하지 말고 원본에서 따로 구해서 비교해.
- 제외하거나 변환한 행이 있으면 건수와 처리 전후 합계를 같이 보여줘.
- 같은 오류로 두 번 실패했어. 고치지 말고 원인 가설 두 개와 확인 방법을 먼저 말해.

## 설명 준비 (서술형 대비)
- 방금 커밋한 변경이 어떻게 동작하는지 한국어 3줄로 설명해. (커밋마다)
- 구조와 데이터 흐름, 그렇게 만든 이유를 비개발자용 5줄로 설명해.

## 완료 보고 (5줄)
- 해결한 문제 / 핵심 숫자 / 검증 방법 / 남은 한계 / 확인받을 결정

## 세션 교체, 압축 뒤
- 지금까지 상태를 HANDOFF.md 에 써: 목표, 끝난 것(증거 포함), 남은 것, 결정, 주의할 점. 그다음 멈춰.
- (`/new` 후) ~/codex-harness/AGENTS.md, TASK.md, DECISIONS.md, HANDOFF.md 를 읽고 지금 단계부터 이어서 해.
- 첫 프롬프트를 다시 붙이지 않는다. 1단계부터 다시 시작해 버린다.

## STATE
- `STATE` 한 단어: 지금 단계 / 남은 일 / 검증 안 된 항목을 3줄로.
