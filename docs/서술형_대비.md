# 서술형 대비 (AI 없이, 문항당 5분)

공개 후기에 따르면 문항은 제출한 작업 기록을 바탕으로 만들어진다. 확인된 공식 정보는 아니다.

## 답 틀 (4문장)
1. 사실: "과제에는 X 라고만 쓰여 있었습니다."
2. 결정: "그래서 Y 로 정했습니다."
3. 근거: "Z 때문이고, 테스트 N 개와 실행 결과로 확인했습니다."
4. 한계: "대신 W 인 경우에는 틀릴 수 있고, 고치려면 V 를 검증해야 합니다."

약점을 물으면: 약한 지점을 구체적으로 지목 > 왜 위험한가 > 다음에 무엇을 검증하겠나.

답에는 파일명, 함수명, 숫자를 넣는다. 질문의 전제가 틀렸으면 첫 문장에서 "실제로는 X 가 아니라 Y 로 처리했습니다"라고 바로잡는다.

## 쓰지 말 것
- 코드에 없는 처리를 있다고 말하기, 숫자를 구현과 다르게 말하기. 기억이 애매하면 "정확한 값은 확인하지 못했습니다".
- 근거 없는 "테스트했습니다" > "테스트 12개 통과, preflight exit 0 을 확인했습니다."
- 모르는 것을 아는 척 > "확인하지 않았습니다. 확인하려면 A 를 보면 됩니다."
- AI 탓, 시간 탓 > "X 를 안 할 일로 정했습니다. 이유는 Y 입니다."

## 예상 질문
의도
- 사용자는 누구고 어떤 결정을 돕나?
- 반드시 지킬 조건과 조정 가능한 것을 어떻게 나눴나?
- 무엇을 가정했고, 틀리면 무엇이 깨지나?
- 하지 않기로 한 것과 이유는?
- Codex 에게 맡긴 것과 직접 한 것의 경계는?
- Codex 출력을 어디서 믿지 않았고 어떻게 확인했나?
- 중간에 방향을 바꾼 적이 있나? 무엇을 보고?

기술
- 실행 방법을 한 줄로. 같은 입력에 같은 출력이 나오나? 동률은?
- 예외나 실패 상황에서 어떻게 되나? 사용자가 알 수 있나?
- 데이터가 10배가 되면 어디가 먼저 문제인가?
- 더 단순한 대안은 왜 부족했나?
- 실패하는 테스트를 직접 본 적이 있나?

자기 인식
- 가장 약한 부분은? 어떤 입력에서 틀리나?
- 설명하지 못하는 코드가 있나?
- 다시 한다면? 시간이 두 배라면?
- 내일 실무에 넣는다면 무엇부터 확인하나?

## 자료를 볼 수 있나
서술형 중에 작업 파일을 볼 수 있는지는 공식 안내에 없다. 볼 수 없다고 가정한다. 종이 메모 허용 여부도 모르므로 당일 안내 메일이나 문의 버튼으로 확인한다.
그래서 동결 때 `DECISIONS.md` 맨 아래에 '서술형 카드'(15줄, 각 줄에 근거)를 만들고, 내가 코드와 대조해 확인한 뒤 외운다.

## 제출 직후, 서술형 전 10분
1. 서술형 카드, `TASK.md` 6, 7번, `DECISIONS.md` 를 다시 읽는다.
2. 아래 세 답을 머릿속으로 완성해 둔다.
   - 상충 조건: "X 와 Y 가 부딪혔고, X 를 반드시 지킬 조건으로 두고 Y 를 조정했습니다. 이유는..."
   - 가장 위험한 실패: "Z 입력에서 틀립니다. 이유는... 고치려면..."
   - Codex 를 믿지 않은 곳: "A 는 맡겼고 B 는 직접 했습니다. 특히 C 는 D 로 다시 확인했습니다."
3. 막히는 질문이 있으면 그것이 문서에 빠진 부분이다.
