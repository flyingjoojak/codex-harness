## 1차 예선(AI 역량 검사) 후기에서 얻은 것
- 컨텍스트를 4분의 3쯤 채우면 틀린 답이 늘었다는 경험담이 있다(sj-park-kr/sk-hynix-hackathon 스크린샷). 자료를 한꺼번에 넣지 말고 나눠 넣고, 길어지면 HANDOFF 후 새 세션.
- 요점은 "AI 가 틀릴 수 있다는 전제로 일을 설계하는 것". 2차 형식과 같다는 근거는 없다.

## 가져오지 않은 것
- 전역 Codex 설정 교체, 승인 우회 플래그가 든 설치 스크립트: 보안 설정 변경 금지 규정과 충돌.
- 외부 접속을 시도하는 정찰 옵션, 시험 날 `git push` 하라는 체크리스트: 규정과 충돌.
- 수백 줄짜리 감사 스크립트, 문서 160개 구조, Ollama, Docker 실험실: 180분 과제에는 과설계.
- 출제 확률, 감점 항목 수, 평가 에이전트 수 같은 출처 없는 단정.
