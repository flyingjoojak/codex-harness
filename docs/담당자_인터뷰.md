# 담당자 인터뷰

과제에 담당자(업무 요청자) 역할의 AI 나 사람이 있으면, 코드를 쓰기 전에 숨은 조건을 캐낸다. 첫 3분은 해법 단어(자동화, AI, 대시보드)를 쓰지 않는다.

## 순서
1. 사례: "이 일이 실제로 벌어진 최근 사례 하나를 구체적으로 알려주세요."
2. 현재 방식: "지금은 누가, 어떤 도구로, 얼마나 걸려서 처리하나요?"
3. 성공 숫자: "잘됐다는 것을 어떤 숫자로 아나요? 지금 값은 얼마고 어디서 재나요?"
4. 손해: "이게 틀리면 누가 얼마나 곤란해지나요? 놓치는 것과 잘못 잡는 것 중 어느 쪽이 더 나쁜가요?"
5. 경계: "예외는 어떤 경우인가요? 절대 건드리면 안 되는 것은? 기준값과 같으면 통과인가요?"
6. 결과 사용자: "결과는 누가 보고, 어떤 결정을 하나요? 어떤 형식이면 바로 쓸 수 있나요?"
7. 합의 확인: 아래 합의문을 읽어 주고 "맞나요?"

## 요령
- "할 일을 알려주세요"처럼 물으면 답이 안 나온다. 업무 장면을 짚어 묻는다.
- 답을 받으면 한 번 더 판다: "왜요?", "그럼 이 경우는요?"
- 사소해 보이는 것(단위, 반올림, 동률 처리, 빈 값)을 일찍 묻는다.
- 답을 유도하지 않는다. "빈 값은 0 으로 넣으면 되죠?" 대신 "값이 없는 기록은 어떤 상태이고, 결과에 어떻게 반영해야 하나요?"
- 담당자가 말하지 않은 숫자는 채우지 않고 `(확인 필요: ...)` 로 남긴다.
- 받은 답은 바로 `TASK.md` 사실 / 가정 표에 옮긴다.

## 합의문 틀
```
문제:
왜 생기나:
성공 기준: 숫자 / 현재값 / 측정 위치
만들 것:
안 만들 것:
제약:
```
