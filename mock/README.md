# 모의 시험 (90분판)

1회차 과제 모양(참가자 공개 기록)을 재구성한 연습용 과제다. 실제 과제 원문이 아니다.
목적은 정답이 아니라 **시간 감각**이다. 구간마다 실제로 걸린 시간을 재서 어디를 줄일지 찾는다.

## 준비 (5분, 시간에 넣지 않는다)
```bash
mkdir -p ~/mock-task && cd ~/mock-task && git init
cp ~/codex-harness/mock/과제.md README.md
python3 ~/codex-harness/mock/make_data.py .
bash ~/codex-harness/setup.sh
git add -A && git commit -m "chore: 모의 과제 시작"
```
담당자 역할: `mock/담당자_답변.md` 는 DM 을 보낸 뒤에만 연다. 질문한 항목의 답만 본다(묻지 않은 것은 모르는 상태로 진행).

## 시간표 (실제 180분을 절반으로 줄였다)
| 구간 | 실제 | 모의 | 끝나는 조건 |
|---|---|---|---|
| 계약과 범위 | 0~20분 | 0~10분 | TASK.md 범위 세 칸, DM 발송 |
| 첫 완주 | 20~70분 | 10~35분 | 필수 기능 end-to-end, 커밋 |
| 개선 | 70~120분 | 35~60분 | 60분에 기능 추가 멈춤 |
| 리뷰 | 120~145분 | 60~72분 | CRITICAL, HIGH 처리 |
| 이해 확인, 제출 | 145~165분 | 72~82분 | UNDERSTANDING 요약 4줄, verify |
| 서술형 | 30분 | 10분 | 아래 5문항을 AI 없이, 문항당 2분 |

## 서술형 (AI 없이, 화면 보지 않고)
1. 노선을 만드는 방식으로 무엇을 택했고, 단순한 방법 대신 그것을 고른 근거와 한계는?
2. 데이터셋 선택부터 내보내기까지 데이터가 거치는 모듈과, 상태를 저장하는 곳은?
3. 구현하고 검증한 것과 가정으로 둔 것은? 평가자는 무엇으로 확인하나?
4. 가장 오래 막힌 문제를 어떻게 발견했고, AI 진단 중 무엇을 받아들이거나 버렸나?
5. 작업 중 구조나 방식을 바꾼 것 하나: 처음엔 무엇이었고 왜 바꿨나, 전환에 든 비용은? (없으면: 구성원 조회 기능이 어떤 과정으로 어떤 모듈을 거치나)

채점: 답에 파일명, 함수명, 숫자가 들어갔나 / 코드와 다른 말이 없나(끝나고 대조) / 막힌 문항은 UNDERSTANDING.md 의 어느 칸이 비어 있었나.

## 끝나고
- 기록표에서 계획보다 5분 넘게 늦은 구간 하나를 골라, GUIDE.txt 나 dev-flow 에서 그 구간을 줄일 방법을 한 줄 적는다.
- 같은 과제를 다시 하지 않는다. 시간 감각을 얻었으면 충분하다.
